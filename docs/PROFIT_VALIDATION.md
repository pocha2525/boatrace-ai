# 回収率によるモデル採用

> 2026-11-28更新：配信は[統合通知](CONSENSUS_NOTICE.md)のconsensus-v1（共通買い目・各点12%/EV1以上・1日1回最大2点）へ変更。以下のcurrent_two/旧買い条件は固定モデル比較と過去記録の条件であり、現行の通知条件ではありません。固定67候補のモデルハッシュ・28日採用基準は維持。明示依頼の再学習は別の研究用artifactへ保存し、自動採用しません。

実装したことと実証したことを区別する。現時点では将来の黒字を実証していない。

## 固定候補

stage-shadow は過去のActionsキャッシュだけから現行材料＋ss_badの候補を一度作る。本番モデルは上書きしない。候補のモデルハッシュ・基準モデルハッシュ・学習打切日・温度を model/shadow/manifest.json に固定し、比較中は候補を上書きしない。直近成績14項目は過去検証で悪化したので追加しない。

predict は同一の取得時点の特徴量で本番と候補の120通りの確率を計算し、同一の締切前オッズと一緒に保存する。候補の通知や購入は行わない。

## 採用条件

作成翌日から最初の連続28日を固定評価期間にする。日を後ろへずらして好都合な期間を選ばない。基準と候補のいずれも200レース以上の購入判定が必要。未確定の払戻があれば採用保留。モデルハッシュ不一致・重複・データ不足は採用不可。

日単位の対応付きbootstrapで、候補回収率の95%区間下限が100%超、かつ基準との差の95%区間下限が0超の場合にのみ採用する。過去精度の採用条件を満たしていなかった候補には、新規500レース以上で対数確率の改善下限0.002以上も要求する。

これはモデル比較の判定基準で、利益の保証ではない。固定期間で条件を満たせなければ不採用のまま。以後の好調日を足して判定を修復しない。新しい候補実験は別の記録・別の未使用期間が必要。

nightly は条件達成時に旧モデル・温度・学習表示を保存し、検証した候補そのものを本番へコピーする。採用時の再学習はしない。履歴に収支の根拠を残す。

## 買い方と私の予想

仮想比較は current_two / first_only / second_ev1 / four_ev1 / shadow_current_two を同じ市場観測で行う。4点は各点100円、2点目以降も期待値1.0以上の比較用で、本番の点数を4点へ変更する処理ではない。

logs/manual_forecasts.jsonl に実在する締切前公表4点と仮想1万円配分だけを記録する。report はその実配分と、同じ4点への各100円配分を別々に採点する。記録不足の日は追加しない。手動予想をモデル学習へ組み込んだという意味ではなく、選定・順位・配分を比較するための記録である。
